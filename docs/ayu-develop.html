Purpose and scope¶

A Rust exchange API abstraction with Binance, Coinbase and Nash implementations and historical C# FFI bindings. OpenLimits is a stateless factory: instantiate returns the concrete venue client E. Venue adapters implement common traits and response models; requests are made on the returned client.

Features¶

  • Common market, balance, order and historical-data models.
  • Venue-specific credentials and environment selection.
  • Streaming interfaces and asynchronous request handling.
  • Optional GMP or num-bigint cryptographic backends.
  • Historical C# interop bindings are separate from the default Rust build.

Runtime workflow¶

  1. Choose venue and environment with appropriate client configuration.
  2. Construct the selected exchange client.
  3. Build a common market or account request.
  4. Let the venue adapter serialize, sign and send the request.
  5. Deserialize the response or propagate OpenLimitsError.

Current exchange protocol compatibility¶

Coinbase product decoding preserves absent historical size limits as None. Coinbase subscriptions select the public batch feed and retain actual parse/transport errors during acknowledgement. Channel types normalize the exchange acknowledgement alias without discarding order-book updates. Binance filters retain current rule fields as typed metadata. These adaptations follow the current official exchange schemas, linked in the development guide.
