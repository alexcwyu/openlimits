Design decisions

Decision Rationale Tradeoff Evidence
Expose a composed Exchange trait with exchange-specific clients. Common requests/results are portable while inner clients retain venue-specific features. Adapters implement different subsets; common trait membership does not mean identical feature coverage. Exchange (L8) / get_historic_rates (L150)
Convert stream messages through TryInto and callbacks. Common consumers can process different native websocket payloads. Callback consumer ends on stream/socket failures; callers must manage lifecycle/recovery. ExchangeStream (L17)

The external exchange is reached by BaseClient, not a native fill simulator. Actual order conversion is inspected; credentials or endpoint connectivity were not exercised in this audit.

Strengths and limits

Strengths

  • Normalized order requests map explicitly to client calls and typed results. limit_buy (L212)

Limitations

  • Sandbox is remote integration, and documented credential/TLS failures remain failures despite current exclusion policy. Environment (L13) / docs/validation.md (L16)
  • Huobi is absent from the supported root exports; Coinbase historical trades is unimplemented. src/exchange/mod.rs (L3) / get_historic_rates (L150)

Validation scope

The linked validation and command records preserve actual historical runs and user-authorized exclusions. This source/document review does not rerun application tests, establish live trading readiness or rank benchmark performance. Current data, credential and runtime prerequisites remain material.
